01

O que é uma API REST?

Conceito

Até agora, suas apps web eram monolitos: um único programa Flask que mexia no banco, decidia a lógica E montava as telas HTML — tudo grudado. A arquitetura profissional separa isso em duas partes independentes:

Backend (API REST)Frontend (cliente)
Python + Flask + MariaDBHTML/JS, app mobile, etc.
Fala só JSON (sem HTML)Mostra as telas
Cuida dos dados e regrasCuida da aparência

Os dois conversam por uma API REST: um conjunto de endereços (endpoints) que recebem pedidos e devolvem JSON. A regra do REST é organizar tudo em torno de recursos (ex.: "produtos") e usar os verbos do HTTP para dizer a operação. É o padrão que move a internet moderna.

EX 01

Monolito vs desacoplado: a grande virada 🏛️

⭐ básico
🎯 Objetivo

Entender por que separar backend e frontend é o jeito profissional.

🧭 Passo a passo
  1. Reflita sobre as vantagens de separar a API do frontend. Para cada situação, pense por que o desacoplamento ajuda:
  2. a) Você quer um site E um app de celular usando os mesmos dados
  3. b) O time de design quer mudar as telas sem mexer na lógica do banco
  4. c) Outra empresa quer integrar o sistema dela com o seu
  5. d) Você quer trocar o frontend de HTML puro para React no futuro
🔑 Ver solução

Só abra depois de tentar!

a) Site e app consomem a MESMA API — você escreve a lógica uma vez. b) Frontend e backend são projetos separados; mudar telas não toca no banco. c) Uma API REST é "plugável": qualquer sistema que fale HTTP+JSON se conecta. d) Troca-se o frontend inteiro sem mexer na API — ela nem fica sabendo. Em uma frase: o monolito é uma peça só (simples de começar, difícil de evoluir); o desacoplado são peças independentes que evoluem sozinhas. É por isso que praticamente toda empresa moderna trabalha assim.

O mapa: verbos HTTP = CRUD

⭐ básico
🎯 Objetivo

O segredo do REST é que cada operação do CRUD (Semana 22) tem um verbo HTTP correspondente:

CRUDVerbo HTTPExemplo
Read (ler)GETGET /api/produtos
Create (criar)POSTPOST /api/produtos
Update (atualizar)PUTPUT /api/produtos/5
Delete (remover)DELETEDELETE /api/produtos/5
🧭 Passo a passo
  1. Só de ler o pedido "DELETE /api/produtos/5", o que você acha que ele faz?
  2. E "GET /api/produtos"? E "POST /api/produtos"?
💡 A elegância do REST
Repare: o MESMO endereço /api/produtos faz coisas diferentes dependendo do VERBO. GET lê, POST cria. O endereço diz o RECURSO; o verbo diz a AÇÃO. Essa clareza é o que torna APIs REST tão fáceis de entender — qualquer dev no mundo lê e já sabe o que acontece.
02

GET: lendo recursos

Conceito

Começamos pelo verbo mais simples. Uma API devolve JSON, então usamos o jsonify (Semana 19). Conecte ao MariaDB (Semana 26) com a função conectar() do seu db.py. E lembre: numa API, nunca se retorna HTML — só dados.

EX 03

GET coleção: a lista de produtos

⭐⭐ médio
🎯 Objetivo

Criar o endpoint que devolve todos os produtos em JSON.

🧭 Passo a passo
  1. Rota /api/produtos com methods=["GET"]
  2. SELECT no MariaDB, monte uma lista de dicionários (list comprehension — Semana 17)
  3. Devolva com jsonify(lista)
api.py
from flask import Flask, jsonify
from db import conectar   # do seu db.py (Semana 26)

app = Flask(__name__)

@app.route("/api/produtos", methods=["GET"])
def listar_produtos():
    conexao = conectar()
    cursor = conexao.cursor()
    cursor.execute("SELECT id, nome, preco, estoque FROM produtos")
    produtos = [
        {"id": id, "nome": nome, "preco": float(preco), "estoque": estoque}
        for id, nome, preco, estoque in cursor.fetchall()
    ]
    conexao.close()
    return jsonify(produtos)

app.run(debug=True)
✅ Saída esperada
terminal
[
  {"id": 1, "nome": "caneca branca", "preco": 25.0, "estoque": 10},
  {"id": 2, "nome": "caneca preta", "preco": 27.5, "estoque": 8}
]
💡 float() no DECIMAL
O tipo DECIMAL do MariaDB vira um objeto especial em Python; o float() o converte para um número que o jsonify entende (lembra do mesmo cuidado com o pandas na Semana 20?). Acesse /api/produtos no navegador: JSON puro, pronto para qualquer cliente consumir.
EX 04

GET item: um produto específico (e o 404)

⭐⭐⭐ desafio
🎯 Objetivo

Buscar um produto pelo id — e responder corretamente quando não existe.

🧭 Passo a passo
  1. Rota /api/produtos/<int:id> (GET)
  2. SELECT WHERE id = %s; se fetchone() devolver None, o produto não existe
  3. Nesse caso, retorne um JSON de erro COM o status 404: return jsonify({"erro": "não encontrado"}), 404
✅ Exemplo
terminal
GET /api/produtos/1  ->  {"id": 1, "nome": "caneca branca", ...}
GET /api/produtos/999  ->  {"erro": "Produto não encontrado"}  (status 404)
💡 O status code importa
Numa API, o CÓDIGO DE STATUS é tão importante quanto o JSON. O 200 diz "deu certo"; o 404 diz "esse recurso não existe". O cliente USA esse número para decidir o que fazer. Retornar 200 com "não encontrado" no texto seria mentir para quem consome a API!
🔑 Ver solução

Só abra depois de tentar!

solucao_ex04.py
@app.route("/api/produtos/<int:id>", methods=["GET"])
def buscar_produto(id):
    conexao = conectar()
    cursor = conexao.cursor()
    cursor.execute("SELECT id, nome, preco, estoque FROM produtos WHERE id = %s", (id,))
    r = cursor.fetchone()
    conexao.close()

    if r is None:
        return jsonify({"erro": "Produto não encontrado"}), 404

    return jsonify({"id": r[0], "nome": r[1],
                    "preco": float(r[2]), "estoque": r[3]})
03

POST: criando recursos

Conceito

Para CRIAR, o cliente envia os dados no corpo da requisição em JSON. No Flask, lemos com request.get_json() (que devolve um dicionário — Semana 5). E ao criar algo com sucesso, o status correto não é 200, e sim 201 ("Created").

EX 05

POST: cadastrar um produto via API

⭐⭐⭐ desafio
🎯 Objetivo

Receber JSON, inserir no banco e responder com 201.

🧭 Passo a passo
  1. Rota /api/produtos com methods=["POST"]
  2. Leia dados = request.get_json() e pegue os campos do dicionário
  3. INSERT no MariaDB com %s + commit
  4. Retorne o produto criado (com o novo id) e o status 201
ex05_post.py
from flask import Flask, jsonify, request
from db import conectar

app = Flask(__name__)

@app.route("/api/produtos", methods=["POST"])
def criar_produto():
    dados = request.get_json()

    conexao = conectar()
    cursor = conexao.cursor()
    cursor.execute(
        "INSERT INTO produtos (nome, preco, estoque) VALUES (%s, %s, %s)",
        (dados["nome"], dados["preco"], dados["estoque"]))
    conexao.commit()
    novo_id = cursor.lastrowid   # o id que o banco gerou
    conexao.close()

    return jsonify({"id": novo_id, **dados}), 201

app.run(debug=True)
✅ Exemplo
terminal
POST /api/produtos
corpo: {"nome": "caneca azul", "preco": 28.0, "estoque": 6}
resposta (201): {"id": 7, "nome": "caneca azul", "preco": 28.0, "estoque": 6}
💡 lastrowid e o **dados
O cursor.lastrowid devolve o id que o AUTO_INCREMENT acabou de gerar. E o **dados (pesquise "desempacotar dicionário"!) "espalha" os campos do dicionário dentro do novo — um truque elegante para devolver o que foi criado já com o id. O 201 avisa o cliente: "criei com sucesso".
04

PUT e DELETE: atualizando e removendo

Conceito

Os dois últimos verbos fecham o CRUD. O PUT atualiza (recebe os novos dados no corpo, como o POST); o DELETE remove (só precisa do id na URL). Ambos devem responder 404 se o recurso não existir.

EX 06

PUT: atualizar um produto

⭐⭐ médio
🎯 Objetivo

Editar um produto existente via API.

🧭 Passo a passo
  1. Rota /api/produtos/<int:id> com methods=["PUT"]
  2. Leia o corpo com get_json, faça o UPDATE com %s e WHERE id
  3. Use cursor.rowcount para saber se alguma linha foi alterada — se 0, retorne 404
✅ Exemplo
terminal
PUT /api/produtos/1  corpo: {"preco": 31.0}  ->  {"ok": true}  (ou 404)
🔑 Ver solução

Só abra depois de tentar!

solucao_ex06.py
@app.route("/api/produtos/<int:id>", methods=["PUT"])
def atualizar_produto(id):
    dados = request.get_json()
    conexao = conectar()
    cursor = conexao.cursor()
    cursor.execute(
        "UPDATE produtos SET nome=%s, preco=%s, estoque=%s WHERE id=%s",
        (dados["nome"], dados["preco"], dados["estoque"], id))
    conexao.commit()
    afetadas = cursor.rowcount
    conexao.close()

    if afetadas == 0:
        return jsonify({"erro": "Produto não encontrado"}), 404
    return jsonify({"ok": True, "id": id})

O rowcount diz quantas linhas o comando mexeu. Zero significa que o WHERE não achou ninguém — ou seja, o id não existe. Daí o 404.

DELETE: remover um produto

⭐⭐ médio
🎯 Objetivo

Apagar um produto via API, com o status certo.

🧭 Passo a passo
  1. Rota /api/produtos/<int:id> com methods=["DELETE"]
  2. DELETE WHERE id = %s + commit
  3. Se rowcount == 0, retorne 404; senão, confirme a remoção
✅ Exemplo
terminal
DELETE /api/produtos/7  ->  {"ok": true, "removido": 7}  (ou 404)
🔑 Ver solução

Só abra depois de tentar!

solucao_ex07.py
@app.route("/api/produtos/<int:id>", methods=["DELETE"])
def remover_produto(id):
    conexao = conectar()
    cursor = conexao.cursor()
    cursor.execute("DELETE FROM produtos WHERE id = %s", (id,))
    conexao.commit()
    afetadas = cursor.rowcount
    conexao.close()

    if afetadas == 0:
        return jsonify({"erro": "Produto não encontrado"}), 404
    return jsonify({"ok": True, "removido": id})

Repare como os quatro verbos sobre o MESMO recurso (/api/produtos) formam um CRUD completo e limpo. Isso é uma API REST bem desenhada.

⭐ básico

CódigoSignificadoQuando usar
200OKGET/PUT/DELETE deu certo

404Not Foundo recurso não existe
401Unauthorizedfalta autenticação (Semana 28!)
🧭 Passo a passo

💡 Família dos códigos
Os 2xx = sucesso; os 4xx = erro do CLIENTE (mandou algo errado); os 5xx = erro do SERVIDOR (deu pau no seu código). Usar o código certo é falar a língua universal do HTTP — todo cliente, em qualquer linguagem, entende.

solucao_ex09.py
@app.route("/api/produtos", methods=["POST"])
def criar_produto():
    dados = request.get_json()

    if not dados or "nome" not in dados or not str(dados.get("nome", "")).strip():
        return jsonify({"erro": "campo nome é obrigatório"}), 400
    try:
        preco = float(dados["preco"])
        estoque = int(dados["estoque"])
    except (KeyError, ValueError, TypeError):
        return jsonify({"erro": "preco e estoque devem ser números"}), 400

    conexao = conectar()
    cursor = conexao.cursor()
    cursor.execute(
        "INSERT INTO produtos (nome, preco, estoque) VALUES (%s, %s, %s)",
        (dados["nome"].strip(), preco, estoque))
    conexao.commit()
    novo_id = cursor.lastrowid
    conexao.close()
    return jsonify({"id": novo_id, "nome": dados["nome"].strip(),
                    "preco": preco, "estoque": estoque}), 201
EX 10

CORS: liberando o frontend 🌍

⭐⭐ médio
🎯 Objetivo

Permitir que um frontend em outro endereço consuma a sua API.

🧭 Passo a passo
  1. Instale: pip install flask-cors
  2. Importe e ative: from flask_cors import CORS e CORS(app)
  3. Pronto — agora um frontend (Semana 29) hospedado em outro endereço pode chamar a API
ex10_cors.py
from flask import Flask, jsonify
from flask_cors import CORS

app = Flask(__name__)
CORS(app)   # libera o acesso de outros endereços (origens)

@app.route("/api/produtos")
def listar():
    return jsonify([{"nome": "caneca branca"}])

app.run(debug=True)
✅ Saída esperada
terminal
(a API agora aceita chamadas vindas de um frontend separado)
💡 Por que CORS existe?
Por segurança, navegadores BLOQUEIAM uma página de um endereço (ex.: seu frontend) de chamar uma API em OUTRO endereço — a menos que a API autorize. O CORS(app) é essa autorização. Sem ele, seu frontend da Semana 29 tomaria erro ao chamar a API. É um detalhe pequeno que trava MUITO iniciante — agora você já sabe!

testar_api.py
import requests

BASE = "http://localhost:5000/api/produtos"

# GET (listar)
r = requests.get(BASE, timeout=5)
print("GET status:", r.status_code)
print("Produtos:", len(r.json()))

# POST (criar)
novo = {"nome": "caneca teste", "preco": 22.0, "estoque": 5}
r = requests.post(BASE, json=novo, timeout=5)
print("POST status:", r.status_code)
print("Criado:", r.json())

Cliente (requests) e servidor (sua API REST), os dois em Python, conversando em JSON via HTTP. É exatamente o que o frontend da Semana 29 fará — só que em JavaScript. Você está testando a API como um profissional.

api.py
from flask import Flask, jsonify, request
from flask_cors import CORS
from db import conectar   # Semana 26

app = Flask(__name__)
CORS(app)

def produto_para_dict(linha):
    return {"id": linha[0], "nome": linha[1],
            "preco": float(linha[2]), "estoque": linha[3]}

@app.route("/api/produtos", methods=["GET"])
def listar():
    con = conectar(); cur = con.cursor()
    cur.execute("SELECT id, nome, preco, estoque FROM produtos")
    lista = [produto_para_dict(l) for l in cur.fetchall()]
    con.close()
    return jsonify(lista)

@app.route("/api/produtos/<int:id>", methods=["GET"])
def buscar(id):
    con = conectar(); cur = con.cursor()
    cur.execute("SELECT id, nome, preco, estoque FROM produtos WHERE id=%s", (id,))
    r = cur.fetchone(); con.close()
    if r is None:
        return jsonify({"erro": "Produto não encontrado"}), 404
    return jsonify(produto_para_dict(r))

@app.route("/api/produtos", methods=["POST"])
def criar():
    d = request.get_json()
    if not d or not str(d.get("nome", "")).strip():
        return jsonify({"erro": "campo nome é obrigatório"}), 400
    try:
        preco, estoque = float(d["preco"]), int(d["estoque"])
    except (KeyError, ValueError, TypeError):
        return jsonify({"erro": "preco e estoque devem ser números"}), 400
    con = conectar(); cur = con.cursor()
    cur.execute("INSERT INTO produtos (nome, preco, estoque) VALUES (%s, %s, %s)",
                (d["nome"].strip(), preco, estoque))
    con.commit(); novo_id = cur.lastrowid; con.close()
    return jsonify({"id": novo_id, "nome": d["nome"].strip(),
                    "preco": preco, "estoque": estoque}), 201

@app.route("/api/produtos/<int:id>", methods=["PUT"])
def atualizar(id):
    d = request.get_json()
    con = conectar(); cur = con.cursor()
    cur.execute("UPDATE produtos SET nome=%s, preco=%s, estoque=%s WHERE id=%s",
                (d["nome"], float(d["preco"]), int(d["estoque"]), id))
    con.commit(); afetadas = cur.rowcount; con.close()
    if afetadas == 0:
        return jsonify({"erro": "Produto não encontrado"}), 404
    return jsonify({"ok": True, "id": id})

@app.route("/api/produtos/<int:id>", methods=["DELETE"])
def remover(id):
    con = conectar(); cur = con.cursor()
    cur.execute("DELETE FROM produtos WHERE id=%s", (id,))
    con.commit(); afetadas = cur.rowcount; con.close()
    if afetadas == 0:
        return jsonify({"erro": "Produto não encontrado"}), 404
    return jsonify({"ok": True, "removido": id})

app.run(debug=True)

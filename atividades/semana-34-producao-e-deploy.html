01

A arquitetura desacoplada na prática

Conceito

Até agora você construiu o backend (a API REST das Semanas 27-28). Agora vem o frontend: uma página separada, em HTML e JavaScript, que CONSOME essa API. São dois projetos independentes que conversam por HTTP:

Frontend (esta semana)Backend (Semanas 26-28)
HTML + JavaScriptPython + Flask + MariaDB
Roda no navegadorRoda no servidor
Pede e mostra dadosGuarda e entrega dados
Chama com fetchResponde com jsonify

Atenção: o frontend é em JavaScript, não Python — é uma linguagem diferente, e é justamente isso que torna o desacoplamento real. A boa notícia: a lógica (buscar dados, mostrar na tela, enviar formulário) é parecida com o que você já faz. E o localStorage você já viu — é onde esta página de exercícios salva o seu XP!

02

fetch: buscando dados da API

Conceito

O fetch é o requests do JavaScript: faz uma requisição HTTP e devolve a resposta. Como leva um tempinho (vai até o servidor e volta), usamos async/await para esperar — parecido com a ideia de aguardar uma resposta que você já viu com APIs na Semana 15.

EX 02

Primeiro fetch: listar produtos

⭐⭐ médio
🎯 Objetivo

Buscar os produtos da API e ver no console.

🧭 Passo a passo
  1. Crie uma função async que faz fetch(API + "/produtos")
  2. Espere a resposta com await e converta com await resp.json()
  3. Mostre no console (F12 no navegador) e chame a função
app.js
async function carregarProdutos() {
  const resp = await fetch(API + "/produtos");
  const produtos = await resp.json();
  console.log("Produtos da API:", produtos);
}

carregarProdutos();
✅ No console do navegador (F12)
terminal
Produtos da API: (Array com os produtos vindos do MariaDB)
💡 fetch é o requests do JS
Compare: no Python era requests.get(url).json(); no JavaScript é await fetch(url) e await resp.json(). Mesma ideia — pedir dados a uma API e receber JSON. O await diz "espere a resposta chegar antes de continuar". Os dados que aparecem vieram do seu backend Python, atravessaram a rede e chegaram ao navegador. Mágico, né? 🪄
EX 03

Mostrando os produtos na tela 🖼️

⭐⭐ médio
🎯 Objetivo

Renderizar a lista no HTML a partir do JSON.

🧭 Passo a passo
  1. Pegue o elemento da lista: document.getElementById("lista")
  2. Monte o HTML percorrendo os produtos (o .map() do JS é como a list comprehension da Semana 17)
  3. Coloque na tela com elemento.innerHTML = ...
app.js
async function carregarProdutos() {
  const resp = await fetch(API + "/produtos");
  const produtos = await resp.json();

  const html = produtos.map(p =>
    `<li>${p.nome} — R$ ${p.preco.toFixed(2)} (${p.estoque} un.)</li>`
  ).join("");

  document.getElementById("lista").innerHTML = "<ul>" + html + "</ul>";
}

carregarProdutos();
✅ Saída esperada
terminal
(a lista de produtos aparecendo formatada na página!)
💡 Os ecos do que você já sabe
O .map() transforma cada produto numa linha de HTML — é a list comprehension (Semana 17) do JavaScript. As crases `...` com ${...} são as f-strings (Semana 2) do JS! Você não está aprendendo do zero — está reconhecendo velhos amigos numa linguagem nova. 😊
03

POST: criando pela tela

Conceito

Para CRIAR, o frontend envia um POST com o corpo em JSON — o espelho do request.get_json() que a API lê (Semana 27). Pegamos os valores de um formulário e mandamos via fetch com method: "POST".

EX 04

Criar produto via fetch 📤

⭐⭐⭐ desafio
🎯 Objetivo

Enviar um novo produto para a API a partir de campos da página.

🧭 Passo a passo
  1. Adicione campos (inputs) e um botão no HTML
  2. No clique, leia os valores e faça fetch com method: "POST", headers de JSON e body: JSON.stringify({...})
  3. Depois de criar, chame carregarProdutos() de novo para a lista atualizar
app.js
async function criarProduto() {
  const nome = document.getElementById("nome").value;
  const preco = parseFloat(document.getElementById("preco").value);
  const estoque = parseInt(document.getElementById("estoque").value);

  await fetch(API + "/produtos", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ nome, preco, estoque })
  });

  carregarProdutos();   // recarrega a lista
}
✅ Saída esperada
terminal
(preenche os campos, clica em criar → produto aparece na lista, vindo do banco)
💡 JSON.stringify = o jsonify ao contrário
A API usa jsonify para virar JSON na SAÍDA; o frontend usa JSON.stringify para virar JSON na ENTRADA. O Content-Type: application/json avisa a API: "estou te mandando JSON". É o handshake que faz frontend e backend se entenderem.
04

Login no frontend: o token e o localStorage

Conceito

Para usar as rotas protegidas (Semana 28), o frontend primeiro faz login na API, recebe o token e o GUARDA no navegador (localStorage). Depois, anexa esse token em cada requisição protegida.

EX 05

Fazendo login e guardando o token 🎫

⭐⭐ médio
🎯 Objetivo

Chamar /api/login e salvar o JWT no navegador.

🧭 Passo a passo
  1. Um formulário de usuário e senha + botão "Entrar"
  2. No clique: fetch POST para /api/login com as credenciais
  3. Pegue o token da resposta e salve: localStorage.setItem("token", dados.token)
app.js
async function login() {
  const usuario = document.getElementById("usuario").value;
  const senha = document.getElementById("senha").value;

  const resp = await fetch(API + "/login", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ usuario, senha })
  });

  if (resp.status === 401) {
    alert("Usuário ou senha inválidos!");
    return;
  }

  const dados = await resp.json();
  localStorage.setItem("token", dados.token);   // guarda o crachá!
  alert("Login feito! ✔");
}
✅ Saída esperada
terminal
(login correto → token salvo no navegador; login errado → alerta de inválido)
💡 O localStorage você já conhece
É a mesma "gavetinha" do navegador onde ESTA página de exercícios guarda o seu XP! Aqui ela guarda o token JWT. Ele fica salvo mesmo se você fechar a aba — por isso sites "lembram" que você está logado. O token é o seu crachá: guardou, agora é só apresentar.
EX 06

Chamadas protegidas com Bearer 🔐

⭐⭐⭐ desafio
🎯 Objetivo

Anexar o token nas requisições que exigem autenticação.

🧭 Passo a passo
  1. Recupere o token: localStorage.getItem("token")
  2. Adicione o cabeçalho "Authorization": "Bearer " + token no fetch
  3. Agora o POST de criar produto funciona como autenticado (Semana 28)
✅ Resultado
terminal
(criar produto agora envia o token → API aceita com 201)
🔑 Ver solução

Só abra depois de tentar!

app.js
async function criarProduto() {
  const token = localStorage.getItem("token");
  const nome = document.getElementById("nome").value;
  const preco = parseFloat(document.getElementById("preco").value);
  const estoque = parseInt(document.getElementById("estoque").value);

  const resp = await fetch(API + "/produtos", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Authorization": "Bearer " + token   // o crachá vai junto!
    },
    body: JSON.stringify({ nome, preco, estoque })
  });

  if (resp.status === 401) {
    alert("Faça login primeiro!");
    return;
  }
  carregarProdutos();
}

Esse "Bearer " + token é exatamente o cabeçalho que o @token_required da Semana 28 lê e valida. As duas pontas — frontend que envia, backend que verifica — finalmente se encaixam. 🤝

05

Tratando erros e saindo

Conceito

Dois acabamentos importantes: reagir ao 401 (token expirou ou sumiu → pedir login) e implementar o "sair" (logout), que no JWT é simplesmente DESCARTAR o token (Semana 28).

EX 07

Excluir via fetch DELETE 🗑️

⭐⭐ médio
🎯 Objetivo

Remover um produto chamando o DELETE da API.

🧭 Passo a passo
  1. Em cada item da lista, um botão que chama excluir(id)
  2. A função faz fetch com method: "DELETE" e o token (rota protegida!)
  3. Recarregue a lista depois
✅ Saída esperada
terminal
(clica em excluir → produto some da lista e do banco)
🔑 Ver solução

Só abra depois de tentar!

app.js
async function excluir(id) {
  const token = localStorage.getItem("token");
  const resp = await fetch(API + "/produtos/" + id, {
    method: "DELETE",
    headers: { "Authorization": "Bearer " + token }
  });
  if (resp.status === 401) {
    alert("Faça login primeiro!");
    return;
  }
  carregarProdutos();
}

Repare como cada verbo HTTP da API (GET, POST, DELETE) tem um fetch correspondente no frontend, mudando só o method. O CRUD inteiro, agora pela tela.

EX 08

O botão "Sair" 👋

⭐⭐ médio
🎯 Objetivo

Implementar o logout descartando o token.

🧭 Passo a passo
  1. Um botão "Sair" que chama localStorage.removeItem("token")
  2. Sem token guardado, as chamadas protegidas voltam a dar 401 (precisará logar de novo)
  3. É o conceito stateless da Semana 28 na prática: o cliente joga o crachá fora
✅ Saída esperada
terminal
(clicou em Sair → token apagado → criar/excluir pedem login novamente)
💡 Logout sem servidor
Lembra que o JWT é stateless (Semana 28)? O servidor não guarda sessão nenhuma — então "sair" é o frontend simplesmente APAGAR o token do localStorage. Simples assim. Toda a "memória" de quem está logado vive no navegador, no token. Elegante e escalável.

EX 09

Projeto: o frontend completo da Tua Caneca 🖥️

⭐⭐⭐ desafio
🎯 Objetivo

Um mini-app de uma página: login, listar, criar e excluir — tudo via API protegida.

🧭 Requisitos
  1. Uma tela com: formulário de login, formulário de novo produto e a lista (com botão excluir em cada item)
  2. Ao carregar, mostra os produtos (GET público); login guarda o token; criar e excluir usam o token
  3. Trate o 401 em todas as ações protegidas
  4. Capriche num <style> simples para ficar apresentável
✅ Saída esperada
terminal
(um app web completo: entra, vê produtos, cadastra e remove — frontend separado falando com a API)
💡 Você fechou o ciclo
Frontend (HTML/JS) ↔ API REST (Flask) ↔ banco (MariaDB), com autenticação JWT no meio. Essa é, literalmente, a arquitetura de aplicações web modernas — a mesma estrutura por trás de sistemas que você usa todo dia. Junte o frontend e a API em dois repositórios no GitHub: é um projeto full-stack de portfólio que impressiona qualquer recrutador. 🏆

  <button onclick="login()">Entrar</button>
  <button onclick="sair()">Sair</button>

  <h3>Novo produto</h3>
  <input id="nome" placeholder="nome">
  <input id="preco" placeholder="preço">
  <input id="estoque" placeholder="estoque">

  <h3>Produtos</h3>

    const API = "http://localhost:5000/api";

    async function carregarProdutos() {

      const produtos = await resp.json();
      document.getElementById("lista").innerHTML = "<ul>" + produtos.map(p =>
        `<li>${p.nome} — R$ ${p.preco.toFixed(2)} (${p.estoque})

      localStorage.removeItem("token");
      alert("Você saiu.");

      });

      carregarProdutos();

        method: "DELETE",
        headers: { "Authorization": "Bearer " + token }
      });
      if (resp.status === 401) { alert("Faça login!"); return; }
      carregarProdutos();
    }

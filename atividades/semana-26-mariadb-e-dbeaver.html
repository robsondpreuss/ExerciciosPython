01

SQLite vs MariaDB: arquivo vs servidor

Conceito

Nas Semanas 21-25 o SQLite foi perfeito para aprender: o banco inteiro num arquivo .db, zero configuração. Mas sistemas reais, com muitos usuários ao mesmo tempo e acesso pela rede, pedem um servidor de banco de dados. É aí que entra o MariaDB (primo livre do MySQL).

Pela redenãosim

Ideal paraapps pequenos, protótipos, aprendersistemas em produção

A ótima notícia: o SQL que você aprendeu (SELECT, WHERE, INSERT, UPDATE, GROUP BY...) é praticamente o MESMO. Muda o "motor" embaixo, não a linguagem em cima.

DBeaver: gerenciando o banco visualmente

Conceito

O DBeaver é uma ferramenta gráfica gratuita para gerenciar bancos de dados — pense nele como um "painel de controle visual" do MariaDB. Com ele você cria bancos, tabelas, roda consultas e VÊ os dados em tabela, sem precisar de código. É o companheiro perfeito do seu Python.

EX 04

Criando o banco e a tabela pelo DBeaver

⭐⭐ médio
🎯 Objetivo

Usar o editor SQL do DBeaver para montar a estrutura.

🧭 Passo a passo
  1. No DBeaver, abra um Editor SQL (SQL Editor → New SQL Script)
  2. Execute o CREATE DATABASE e depois o CREATE TABLE abaixo

  4. VARCHAR e DECIMAL
criar.sql
CREATE DATABASE IF NOT EXISTS tua_caneca;
USE tua_caneca;

CREATE TABLE IF NOT EXISTS produtos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100),
    preco DECIMAL(10,2),
    estoque INT
);
✅ Saída esperada
terminal
(banco tua_caneca e tabela produtos criados — visíveis na árvore à esquerda)
💡 Tipos do MariaDB
No SQLite os tipos eram "soltos" (TEXT, REAL). No MariaDB eles são mais precisos: VARCHAR(100) = texto até 100 caracteres; DECIMAL(10,2) = número com 2 casas decimais (perfeito para dinheiro!); INT = inteiro. E AUTO_INCREMENT substitui o AUTOINCREMENT do SQLite. Pequenas diferenças, mesma ideia.
03

PyMySQL: conectando do Python

Conceito

Para conversar com o MariaDB pelo Python, usamos a biblioteca PyMySQL (pip install pymysql). A boa notícia: a interface é quase idêntica ao sqlite3 — connect, cursor, execute, commit. A diferença principal está na CONEXÃO (precisa de host, usuário e senha) e nos placeholders.

EX 05

A primeira conexão (com credenciais seguras) 🔐

⭐⭐ médio
🎯 Objetivo

Conectar ao MariaDB do Python, sem expor a senha no código.

🧭 Passo a passo
  1. Instale: pip install pymysql
  2. Guarde as credenciais em variáveis de ambiente (lição da Semana 24!) e leia com os.environ.get
  3. Conecte passando host, user, password e database
ex05_conexao.py
import os
import pymysql

conexao = pymysql.connect(
    host=os.environ.get("DB_HOST", "localhost"),
    user=os.environ.get("DB_USER", "root"),
    password=os.environ.get("DB_PASS", ""),
    database="tua_caneca"
)

print("Conectado ao MariaDB! ✔")
conexao.close()
✅ Saída esperada
terminal
Conectado ao MariaDB! ✔
💡 Credenciais nunca no código
Assim como a chave de IA (Semana 24), a senha do banco JAMAIS deve ficar escrita no código (e muito menos no GitHub!). As variáveis de ambiente DB_HOST, DB_USER, DB_PASS mantêm o segredo fora do código. O segundo valor em os.environ.get("DB_USER", "root") é um padrão, usado se a variável não existir.

import os
import pymysql

try:
    conexao = pymysql.connect(
        host=os.environ.get("DB_HOST", "localhost"),
        user=os.environ.get("DB_USER", "root"),
        password=os.environ.get("DB_PASS", ""),

    conexao.close()
except pymysql.err.OperationalError as erro:
    print(f"Falha ao conectar: {erro}")

Tratar a falha de conexão é essencial: bancos caem, senhas mudam, a rede oscila. Um bom programa avisa o problema em vez de explodir.

04

CRUD no MariaDB: a diferença do %s

Conceito

A mudança mais visível ao sair do SQLite: os placeholders deixam de ser ? e passam a ser %s. Fora isso, execute, fetchall, commit — tudo igual. O resto do SQL não muda em nada.

EX 07

INSERT com %s

⭐⭐ médio
🎯 Objetivo

Inserir produtos no MariaDB.

🧭 Passo a passo
  1. Use %s no lugar de cada ? (a única mudança no comando!)
  2. O valor vai numa tupla, exatamente como antes
  3. Não esqueça o commit()
ex07_insert.py
import os
import pymysql

conexao = pymysql.connect(host=os.environ.get("DB_HOST", "localhost"),
    user=os.environ.get("DB_USER", "root"),
    password=os.environ.get("DB_PASS", ""), database="tua_caneca")
cursor = conexao.cursor()

cursor.execute(
    "INSERT INTO produtos (nome, preco, estoque) VALUES (%s, %s, %s)",
    ("caneca branca", 25.00, 10)
)
conexao.commit()
conexao.close()
print("Produto inserido no MariaDB ✔")
✅ Saída esperada
terminal
Produto inserido no MariaDB ✔
💡 ? virou %s
No SQLite: VALUES (?, ?, ?). No MariaDB com PyMySQL: VALUES (%s, %s, %s). É a mesma proteção contra SQL injection (Semana 21) — só muda o símbolo. O %s aqui NÃO é formatação de string; é o placeholder do driver. Continue passando os valores na tupla separada!

05

A migração: SQLite → MariaDB

Conceito

Você tem dados no loja.db (SQLite, das Semanas 21-25) e quer levá-los para o MariaDB. A estratégia é simples e poderosa: ler de um banco e gravar no outro, no mesmo script. Os dois módulos (sqlite3 e pymysql) convivem numa boa.

EX 10

O script de migração 📦

⭐⭐⭐ desafio
🎯 Objetivo

Transferir todos os produtos do SQLite para o MariaDB.

🧭 Passo a passo
  1. Abra DUAS conexões: uma com sqlite3 (origem) e uma com pymysql (destino)
  2. SELECT tudo da tabela do SQLite (fetchall)
  3. Para cada linha, INSERT no MariaDB com %s
  4. commit no destino e confira a contagem
✅ Exemplo de execução
terminal
4 produtos migrados do SQLite para o MariaDB ✔
💡 Dois bancos, um script
Lembra de ler CSV e gravar no banco (Semana 21)? Aqui é o mesmo padrão "ler de uma fonte, gravar em outra" — só que a fonte é outro banco. Esse tipo de script (chamado de "ETL" no mercado: Extract, Transform, Load) é tarefa comum e bem valorizada.
🔑 Ver solução

Só abra depois de tentar!

migrar.py
import os
import sqlite3
import pymysql

# ORIGEM: SQLite
origem = sqlite3.connect("loja.db")
cur_origem = origem.cursor()
cur_origem.execute("SELECT nome, preco, estoque FROM produtos")
produtos = cur_origem.fetchall()
origem.close()

# DESTINO: MariaDB
destino = pymysql.connect(host=os.environ.get("DB_HOST", "localhost"),
    user=os.environ.get("DB_USER", "root"),
    password=os.environ.get("DB_PASS", ""), database="tua_caneca")
cur_destino = destino.cursor()

for nome, preco, estoque in produtos:
    cur_destino.execute(
        "INSERT INTO produtos (nome, preco, estoque) VALUES (%s, %s, %s)",
        (nome, preco, estoque))

destino.commit()

cur_destino.execute("SELECT COUNT(*) FROM produtos")
total = cur_destino.fetchone()[0]
destino.close()

print(f"{len(produtos)} produtos migrados do SQLite para o MariaDB ✔")

Projeto: BancoProdutos no MariaDB 🗄️

⭐⭐⭐ desafio
🎯 Objetivo

Adaptar a classe da Semana 22 para o MariaDB — mesma interface, novo motor.

🧭 Requisitos
  1. Pegue a classe BancoProdutos da Semana 22 (CRUD encapsulado)
  2. Troque a conexão sqlite3 por pymysql (com credenciais de ambiente)
  3. Troque todos os ? por %s
  4. Os MÉTODOS (inserir, listar, vender, buscar) continuam com a mesma assinatura — quem usa a classe nem percebe a troca!
✅ Exemplo de execução
terminal
Produto inserido ✔
caneca natal — R$ 30.00 (15 un.)
Venda ok! Novo estoque: 12
💡 A beleza do encapsulamento
Como o CRUD está "escondido" dentro da classe (Semana 22), trocar SQLite por MariaDB mexe SÓ no interior dela. O resto do programa, que só chama banco.inserir(...), continua intacto. Isso é o poder da abstração: trocar o motor sem trocar o painel. 🏎️
🔑 Ver solução

Só abra depois de tentar!

banco_mariadb.py
import os
import pymysql

class BancoProdutos:
    def __init__(self):
        self.conexao = pymysql.connect(
            host=os.environ.get("DB_HOST", "localhost"),
            user=os.environ.get("DB_USER", "root"),
            password=os.environ.get("DB_PASS", ""),
            database="tua_caneca")
        self.cursor = self.conexao.cursor()

    def inserir(self, nome, preco, estoque):
        self.cursor.execute(
            "INSERT INTO produtos (nome, preco, estoque) VALUES (%s, %s, %s)",
            (nome, preco, estoque))
        self.conexao.commit()
        print("Produto inserido ✔")

    def listar(self):
        self.cursor.execute("SELECT * FROM produtos ORDER BY nome")
        for id, nome, preco, estoque in self.cursor.fetchall():
            print(f"{nome} — R$ {preco:.2f} ({estoque} un.)")

    def vender(self, nome, qtd):
        self.cursor.execute("SELECT estoque FROM produtos WHERE nome = %s", (nome,))
        r = self.cursor.fetchone()
        if r is None or r[0] < qtd:
            print("Venda não realizada.")
            return
        self.cursor.execute(
            "UPDATE produtos SET estoque = estoque - %s WHERE nome = %s", (qtd, nome))
        self.conexao.commit()
        print(f"Venda ok! Novo estoque: {r[0] - qtd}")

    def fechar(self):
        self.conexao.close()

# --- teste ---
banco = BancoProdutos()
banco.inserir("caneca natal", 30.0, 15)
banco.listar()
banco.vender("caneca natal", 3)
banco.fechar()

Compare com a versão SQLite da Semana 22: 95% idêntica. Você não reaprendeu nada — só adaptou. É assim que o conhecimento bem construído se paga.

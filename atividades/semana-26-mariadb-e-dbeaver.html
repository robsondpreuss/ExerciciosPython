EX 02

Caça aos bugs de engenharia 🐛🔍

⭐⭐⭐ desafio
🎯 Objetivo

Os tropeços clássicos do módulo, todos num só lugar.

🧭 Passo a passo
  1. O teste abaixo deveria validar o relatório da API — ache os 4 bugs:
test_bugado.py
from api import app

def testar_relatorio():
    client = app.test_client()
    resp = client.get("/api/relatorio/ranking")
    assert resp.status_code == 200

# consulta usada na rota:
# SELECT p.nome, SUM(v.qtd) FROM vendas v
# JOIN produtos p WHERE p.id = v.produto_id
# GROUP BY p.nome
🔑 Ver solução

Só abra depois de tentar!

Os 4 bugs: (1) a função chama-se testar_relatorio — o pytest só coleta funções que COMEÇAM com test_; esse teste nunca roda (o mais silencioso dos bugs: a suíte fica verde... vazia!). (2) A rota é protegida (Semana 31: relatórios com @token_required) — sem o header Authorization, o status esperado seria 401, não 200; o teste precisa logar e enviar o token. (3) No SQL, a condição de junção usa WHERE no lugar de ON — a sintaxe do JOIN exige JOIN produtos p ON p.id = v.produto_id. (4) A coluna agregada não tem alias (AS unidades) — funciona, mas dificulta o ORDER BY e a leitura; num relatório profissional, sempre batize as agregações.

test_corrigido.py
from api import app

def test_relatorio_exige_token():
    client = app.test_client()
    resp = client.get("/api/relatorio/ranking")
    assert resp.status_code == 401   # protegido!

def test_relatorio_com_token():
    client = app.test_client()
    login = client.post("/api/login",
        json={"usuario": "robson", "senha": "tuacaneca123"})
    token = login.get_json()["token"]
    resp = client.get("/api/relatorio/ranking",
        headers={"Authorization": f"Bearer {token}"})
    assert resp.status_code == 200
    assert isinstance(resp.get_json(), list)

  2. a) Pesquise "GitHub Actions pytest" e faça os testes rodarem SOZINHOS a cada push (CI — integração contínua!)
